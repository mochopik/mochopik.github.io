# Hugo Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `mochopik.github.io` into a Hugo + PaperMod technical blog deployed by GitHub Actions, keeping `/privacy.html` live.

**Architecture:** Hugo project at repo root, PaperMod as git submodule, static privacy page in `static/`, GitHub Actions builds `public/` and deploys to Pages.

**Tech Stack:** Hugo 0.169 extended (local), PaperMod theme, GitHub Actions (`actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`).

**Spec:** `docs/superpowers/specs/2026-11-21-hugo-blog-design.md`

## Global Constraints
- `baseURL = "https://mochopik.github.io/"`, `languageCode = "id"`, `title = "mochopik"`.
- `/privacy.html` must keep the exact current content and URL.
- `public/` and `resources/_gen/` are not committed.
- No email address, client ID or client secret anywhere in the site.
- Repo: `~/Projects/playground/mochopik.github.io`, branch `main`, remote `mochopik/mochopik.github.io`.

## Review Focus
- Switching Pages source: if code is pushed while Pages is still "legacy/branch", the raw repo is served and `/` + `/privacy.html` 404 → switch to `build_type=workflow` BEFORE pushing (Task 4).
- Submodule not checked out in CI → empty site; workflow must use `submodules: recursive` (Task 4).
- Search page empty if home JSON output is missing → assert `public/index.json` exists (Task 2).
- `docs/` folder must not leak into the built site → assert `public/docs` absent (Task 1).
- Post leaking personal data → grep the build for `@gmail.com` and `apps.googleusercontent.com` (Task 3).
